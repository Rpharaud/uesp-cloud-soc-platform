# SECAR Dashboard Specification

## Purpose

The **Security Engineering & Cloud Architecture Residency (SECAR) Dashboard** serves as the primary operational dashboard for the residency. It provides a centralized view of engineering progress, learning objectives, project milestones, certification readiness, and career development throughout the program.

Success is measured through objective engineering metrics, technical deliverables, certification progress, architectural maturity, interview readiness, and career development milestones. The primary outcome of the residency is to develop a well-rounded Security Engineer capable of designing, implementing, operating, and defending modern cloud-native environments while demonstrating strong engineering, architectural, and communication skills.

---

## Dashboard Structure

The dashboard is organized into the following sections:

* Residency Health
* Current Phase
* Current Sprint
* Weekly Objectives
* Certifications
* Active Projects
* Reading Queue
* Key Performance Indicators (KPIs)
* Upcoming Design Reviews
* Career Progress
* GitHub Activity
* Interview Readiness
* Resume Progress

---

## Section Specifications

## Residency Health

Provides a high-level assessment of the residency.

Tracks:

* Overall Status
* Sprint Health
* Certification Health
* Portfolio Health
* Interview Readiness
* Architecture Maturity
* Burnout Risk

---

## Current Phase

Tracks the active residency phase.

Includes:

* Phase title
* Objectives
* Expected deliverables
* Entry criteria
* Exit criteria

---

## Current Sprint

Tracks the currently active sprint.

Sprint identifiers follow:

`Phase[#].Sprint[#]`

Example:

`2.3`

Each sprint records:

* Sprint objective
* Planned deliverables
* Sprint status
* Completion percentage

---

## Weekly Objectives

Tracks the weekly objectives required to complete the active sprint.

Weekly objectives should directly support sprint completion.

---

## Certifications

Tracks certification progress.

Categories include:

* Active
* Planned
* Backlog
* Completed

---

## Active Projects

Tracks all projects associated with the residency.

Each project records:

* Status
* Owner
* Sprint
* Priority
* Completion Percentage

---

## Reading Queue

Tracks required reading supporting:

* Current sprint objectives
* Certifications
* Architecture
* Security engineering

---

## Key Performance Indicators (KPIs)

KPIs objectively measure residency progress.

Suggested metrics include:

* Git commits per week
* Pull Requests completed
* Architecture Decision Records (ADRs)
* Sprint completion percentage
* Documentation coverage
* Labs completed
* Interview questions mastered
* Books completed
* Architecture reviews completed

Additional KPIs may be added as the residency matures.

---

## Upcoming Design Reviews

Tracks all scheduled design reviews.

Each review records:

* Agenda
* Artifacts
* Attendees
* Outcomes
* Follow-up actions

---

## Career Progress

Tracks career development throughout the residency.

Areas include:

* Resume completion
* LinkedIn updates
* Portfolio updates
* Applications submitted
* Interviews completed
* Recruiter contacts
* Salary target
* Target companies

---

## GitHub Activity

Tracks repository health and engineering activity.

Includes:

* Latest commit hash
* Current branch
* Repository health
* Latest release
* Latest tag
* Open Issues
* Open Pull Requests

---

## Interview Readiness

Tracks readiness across engineering domains.

Suggested domains:

* Cloud Computing
* Networking
* Linux
* Containers
* Kubernetes
* Terraform
* AWS
* Python
* Security Engineering
* Threat Detection
* System Design
* Behavioral Interviews

Each domain should be periodically assessed using a standardized readiness score.

---

## Resume Progress

Tracks resume development.

Includes:

* Experience bullets
* Quantified accomplishments
* Project evidence
* Portfolio links
* Technical skills
* Certifications
* Revision history

---

## Dashboard Update Policy

The operational dashboard shall be updated:

* At the beginning of every sprint
* At the conclusion of every sprint
* Following major architectural decisions
* Following certification completion
* Following significant project milestones

---

## Definition of Success

The SECAR Dashboard is considered successful when it provides an accurate, measurable, and current representation of residency progress, enabling informed engineering, architectural, and career development decisions throughout the program.
