# THEORY

## Purpose

This document captures the core theory behind the UESP Cloud SOC Platform. The goal is to understand the security concepts before implementing tools.

---

## SOC Fundamentals

A Security Operations Center exists to monitor, detect, investigate, and respond to security events.

Core SOC functions include:

- Telemetry collection
- Alert triage
- Threat detection
- Incident investigation
- Escalation and response
- Continuous tuning

---

## Telemetry

Telemetry is security-relevant data generated by systems, users, applications, networks, and cloud services.

Examples:

- Authentication logs
- API activity
- Network flows
- Endpoint events
- DNS requests
- Process activity
- IDS alerts

Good telemetry should be:

- Relevant
- Timely
- Searchable
- Correlatable
- Retained long enough for investigation

---

## Cloud Security Monitoring

Cloud environments require visibility into control plane and data plane activity.

For AWS, important telemetry sources include:

- CloudTrail
- GuardDuty
- Security Hub
- VPC Flow Logs
- IAM activity
- EC2 system logs

CloudTrail is especially important because it records API activity.

---

## Detection Engineering

Detection engineering is the process of creating, testing, tuning, and maintaining logic that identifies suspicious or malicious behavior.

Detection approaches include:

- Signature-based detection
- Behavioral detection
- Anomaly detection
- Threat intelligence matching
- Correlation-based detection

Behavioral detections are especially valuable because they focus on what attackers do, not just known indicators.

---

## MITRE ATT&CK

MITRE ATT&CK provides a structured way to describe attacker behavior.

Key terms:

- Tactic: attacker objective
- Technique: method used to achieve the objective
- Procedure: specific real-world implementation

Example:

- Tactic: Credential Access
- Technique: Brute Force
- Procedure: password spraying against cloud accounts

---

## Incident Response

Incident response follows a lifecycle:

1. Preparation
2. Detection and Analysis
3. Containment
4. Eradication
5. Recovery
6. Lessons Learned

The SOC platform should support detection, investigation, evidence collection, and response planning.

---

## Validation Engineering

Security controls must be tested, not assumed.

Validation includes:

- Functional testing
- Security testing
- Edge-case testing
- Failure testing
- Adversarial testing
- Recovery testing

A detection is not complete until it has been tested and documented.
